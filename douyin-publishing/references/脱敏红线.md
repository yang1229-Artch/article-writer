# 脱敏红线（隐私与安全核查清单）

> 先查红线，再谈传播。任何真实经历类文章，发布前逐项过。

## 必守红线（每条都是硬约束）

1. **聊天截图必须打码**：头像、昵称、备注名、时间、群名、地点全部抹掉，只留对话文字。打码不是可选的美化，是发布底线。
2. **原话保留需用户拍板**：涉及对方的原话（如"现在不想谈恋爱"）虽然是钩子资产，但属于对方的声音——发布前必须由用户确认可以公开，不替用户决定。
3. **不泄露对方可识别信息**：姓名、职业、城市、学校、家庭背景、共同朋友，一个都不写。判断标准：看到文章的人能否顺着信息认出对方。
4. **他人评价只概括不引述**：朋友/他人的负面评价，转述成概括（"几条，全是负面：没付出过、拖了这么久…"），不贴原文、不露身份。
5. **发布范围确认**：私人创作默认不进公开仓库/开源项目；草稿落盘在 git 仓库内时要确认被 .gitignore 排除或用户明确同意公开。

## 核查问句（发布前逐条问）

- [ ] 每张截图是否已打码（头像/昵称/时间/地点）？
- [ ] 涉及对方的原话，用户是否已确认可以公开？
- [ ] 文中是否有任何信息能让人"认出"对方？
- [ ] 他人评价是否只做了概括、未引述？
- [ ] 文件/草稿是否落在安全位置（私有或已 ignore）？

## 原则

- 真实感来自细节，但细节的边界是：**不伤害对方、不暴露对方**。
- 模糊化处理（隐去时间、概括评价、打码截图）不损失真实感——读者的共鸣来自情绪，不来自精确信息。
- 用户对发布风险有疑虑时，倾向保守：能不发就不发，能概括不引述。
